## 一、文档信息与使用说明

本清单由 reference.md（PRD + Technical Design V3.1）派生而成，是 NexusAI Lite（智枢 AI 错峰调度与夜间开发工具）的开发、测试与验收基线。本版本为单用户/小团队范围，聚焦错峰调度与夜间开发主线，V3.0 中的企业级范围已移除。开发团队或 AI 开发 Agent 可自上而下逐条执行。

**使用方式：**

- 每个任务为复选框项 `- [ ]`。完成并验证验收标准后，将 `[ ]` 标记为 `[x]`。
- 任务具有唯一 ID。ID 方案：
  - `S1-xx` = 阶段 1 监控（S1）。
  - `S2-xx` = 阶段 2 错峰（S2）。
  - `S3-xx` = 阶段 3 夜间开发（S3）。
  - `S4-xx` = 阶段 4 优化（S4）。
  - `X-xx` = 横向任务（测试、交付物、配置、安全负向测试等）。
- 当任务 A 依赖任务 B 时，通过 `前置依赖 = B 的 ID` 引用，保持 ID 稳定不变。
- 优先级：高 = 安全与核心主线、不可省略；中 = 主线功能的强化；低 = 可选增强。安全相关任务（沙箱、密钥、白名单、预算硬上限）与核心主线（采集、分析、错峰、夜间开发）默认为「高」。
- 复杂度：S（小）/ M（中）/ L（大），用于排序与排期参考，不含人天估算。
- 每个阶段首部列出该阶段在 reference.md §8 中的退出条件，任务完成后据此判定阶段是否通关。
- `来源` 列标注对应 reference.md V3.1 的 F 编号或章节号（F1–F8、§0–§13），便于回溯原文。

**重要约定：**

- reference.md §11（已知限制与待确认项）中的待确认决策属于**人工业务决策**，不是开发 Agent 可自行拍板的项。清单中将这些项列为「阻塞项」表格，并建议安全默认值。开发 Agent 不得在未获授权时自行扩大权限、成本或安全边界。
- 数据边界原则（§1）为硬约束：官方公开信息采集与自身调用数据统计必须分开，不得声称可观察或推断供应商全局流量/内部队列/真实剩余配额。
- 安全、预算硬上限、生产变更等关键项默认需要人工审批，遵守 §12 硬性规则。
- 技术栈（§5.3）仅作建议，不得被当作硬性需求。

## 三、阶段 1：监控（S1）

**§8 退出条件：** 官方信息与自身调用数据分开记录并均可追踪；两类数据来源清晰不混淆；统计包含数据质量标记。

| ID | 标题 | 优先级 | 复杂度 |
|---|---|---|---|
| S1-01 | 官方价格页+状态页采集器 | 高 | M |

- **目标：** 定时抓取 DeepSeek 官方价格页与服务状态页并保存快照。
- **交付物：** 官方采集器模块、`official_snapshots` 表写入逻辑、抓取失败处理。
- **前置依赖：** 无
- **来源：** F1、§1.1、§6
- **验收标准：**
  - [ ] 定时抓取官方价格页与服务状态页，保存快照与抓取时间。
  - [ ] 服务状态页用于识别服务异常时段；不作为全局请求量监控。
  - [ ] 抓取失败或内容无法解析时记录失败，不伪造默认值并当作权威数据。
  - [ ] 每次快照记录数据来源（官方渠道）与采集时间，与自身观测分开存储。
- **提示：** 官方未公开全局请求量、用户峰值或内部排队信息；若爬虫抓不到就记录失败，不得伪造推断（§1.2）。

- **交付物：** 时段解析器、`window_rules` 规则表、初始默认规则与来源标记。
- **前置依赖：** S1-01
- **来源：** F1、§1.1、§6

  - [ ] 规则写入 `window_rules` 并标记数据来源与采集时间。
  - [ ] 明确该规则为「计价时段定义」、可配置的初始调度规则，不等于全局实时访问曲线。
  - [ ] 支持人工修改为可配置规则，并作为版本化配置管理（§7）。

- **交付物：** API Client 模块、Provider Adapter 接口、流式/非流式处理、统一错误分类、有限重试钩子。

  - [ ] Provider Adapter 封装供应商请求格式、错误分类、`Retry-After`、Usage 与模型能力，可独立测试升级（§0.3 原则 8）。

  - [ ] 未知错误采用保守处理，不因无法识别而无限重试（F5/§12 规则 4）。

## 四、阶段 2：错峰（S2）

**§8 退出条件：** 高峰时段非紧急任务被降载/延迟而重要任务受保护；429/503 触发退避与有限重试；状态不确定时不会盲目重试；预算硬上限不会被并发竞争突破；决策可解释并可定位到规则版本。

| ID | 标题 | 优先级 | 复杂度 |
|---|---|---|---|
| S2-01 | 任务状态机 + 持久化任务表 | 高 | L |

- **目标：** 实现精简状态机与持久化任务表，状态转换由事务保护。
- **交付物：** `tasks`/`task_runs`/`task_attempts` 表、状态机、状态转换事务。
- **前置依赖：** S1-08、S1-03
- **来源：** §3、F6、§6、§12 规则 2
- **验收标准：**
  - [ ] 状态集为精简集：PENDING/QUEUED/RUNNING/RETRY_WAIT/PAUSED/SUCCEEDED/FAILED/CANCELLED/EXPIRED/UNKNOWN，各状态转换有合法性定义。
  - [ ] 每个任务有 `task_id`；每次执行有 `execution_id`；每次尝试有 `attempt_id` 与 `attempt_no`。
  - [ ] 状态转换由数据库事务或等效原子机制保护；记录 `created_at`/`started_at`/`finished_at`/`deadline_at`。
  - [ ] 任务支持最大执行时长、最大 Attempt 数与最大累计成本上限。

| ID | 标题 | 优先级 | 复杂度 |
|---|---|---|---|
| S2-02 | 幂等创建与去重 | 高 | M |

- **目标：** 实现任务幂等创建与重复投递去重，避免重复创建与重复执行。
- **交付物：** 幂等键处理、消费者幂等、去重机制。
- **前置依赖：** S2-01
- **来源：** F6、§3、§12 规则 2
- **验收标准：**
  - [ ] 同一幂等键在有效期内重复提交不创建重复任务。
  - [ ] 队列消息允许至少一次投递，消费者必须幂等；重复投递不重复创建或重复执行。
  - [ ] 状态不确定时不得盲目重试（进入 `UNKNOWN`），提供人工处理入口（§12 规则 3）。

| ID | 标题 | 优先级 | 复杂度 |
|---|---|---|---|
| S2-03 | 有限重试、失败恢复与 UNKNOWN 处理 | 高 | M |

- **目标：** 实现有限重试、任务恢复与 `UNKNOWN` 人工处理。
- **交付物：** 重试策略、恢复逻辑、`UNKNOWN` 人工处理入口。
- **前置依赖：** S2-01、S2-02
- **来源：** F6、§3、§4.4、§12 规则 3/4
- **验收标准：**
  - [ ] 状态不确定时不得盲目重试；进入 `UNKNOWN` 并提供人工处理入口（§3、§4.4）。
  - [ ] 重试受次数、时间与成本上限约束；每次重试有可追踪原因（§12 规则 4）。
  - [ ] 执行进程崩溃或重启后先核查上次执行记录与外部副作用状态，不得盲目重试（§3）。
  - [ ] 支持人工取消、暂停与恢复；任务取消记录取消时间与可能的残余外部执行。
  - [ ] 系统重启后能区分可安全恢复任务与需人工确认任务。

| ID | 标题 | 优先级 | 复杂度 |
|---|---|---|---|
| S2-04 | 429/503 退避与有限重试 | 高 | M |

- **目标：** 实现限流退避与有限重试，作为错峰的重要反馈机制。
- **交付物：** `Retry-After` 处理、指数退避+抖动、重试次数/时间/成本上限。
- **前置依赖：** S1-03、S2-03
- **来源：** F5、§1.1、§12 规则 4
- **验收标准：**
  - [ ] 对 429 优先遵守 `Retry-After`；若不存在用有限指数退避与随机抖动。
  - [ ] 重试有次数、总重试时间与总成本上限；明显不可重试的 4xx（参数错误、权限错误）不自动重试。
  - [ ] 对认证错误优先停止并告警，不得反复尝试同一失效密钥。
  - [ ] 503 视为服务过载信号，触发减少并发或延迟非紧急任务（F5、§1.1）。

| ID | 标题 | 优先级 | 复杂度 |

## 八、阻塞项与待确认项（§11）

以下决策需在开发启动前由使用方确认，属于**人工业务决策**。开发 Agent 不得自行拍板会扩大权限或成本的项；在未确认前，按「建议安全默认值」落地并在配置中显式标记为待定，采用安全默认值（§0.3 原则 4）。

| 决策项 | 影响 | 建议安全默认值 | 受影响任务 ID |
|---|---|---|---|
| 目标用户为单人/小团队；并发量与吞吐目标 | 影响容量规划与压测基线 | 单用户/小团队起步，不虚构固定 QPS 容量（§5.3） | X-01、X-03 |
| 官方计价时段作为初始调度规则的复核周期 | 影响调度规则准确性 | 以官方价格页为准并定期复核；标记数据来源与采集时间 | S1-02、S1-01 |
| 沙箱采用容器还是受限本地环境；允许的网络范围 | 影响隔离强度与能力 | 非 root、禁 privileged、禁 Docker Socket、限制资源、默认关闭出站网络或白名单 | S3-03、X-02 |
| 夜间开发允许读取和修改的仓库/目录范围 | 影响命令/目录白名单 | MVP 仅生成分支/补丁草案供人工检查；仓库与目录范围最小化 | S3-04、S3-06 |
| 预算币种、价格来源与硬上限数值 | 影响预算与成本限制 | 预算硬上限不被自动突破；价格表按官方计价版本版本化 | S2-07、S1-09 |
| 生产合并/部署/数据库变更的审批责任人 | 影响人工控制点 | 全由使用方本人审批；禁止自动合并与自动部署 | S3-06 |
| 数据保留期限与日志脱敏程度 | 影响日志与合规 | 默认不保存完整 Prompt/响应；L4 秘密数据不进日志/指标/告警 | S1-07 |
| 是否延后支持多 Provider、多租户 | 影响范围边界 | 首期仅 DeepSeek；多 Provider/多租户均延后，不纳入 MVP | X-03（路线图） |
