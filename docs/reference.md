# 0. 文档说明、定位与范围收缩

## 0.1 项目定位与需求主线

NexusAI Lite 是一个面向个人或小团队的智能 API 错峰调度与夜间开发工具，核心需求主线为：

1. **采集信息：** 采集 DeepSeek 官方公开的 API 服务状态与计价时段相关信息（高峰/空闲计价时段、官方服务状态页、已文档化的错误语义）。
2. **分析规律：** 按工作日工作时间 / 夜间 / 周末 / 节假日，基于官方时段规则与本工具自身观测到的调用数据，分析错峰规律。
3. **自动错峰：** 在预测的高峰时段，降低非紧急 API 任务的优先级并限流，同时保护重要任务。
4. **夜间开发：** 在允许的夜间 / 非工作日窗口内，自动启动已授权的开发程序，利用可用 API 容量执行开发任务。
5. **结果反馈：** 记录实际调用效果、任务进度与成本，并据此逐步改进调度规则。

系统应先实现可观测、可控、可恢复的基础能力，再逐步引入历史分析与预测。技术栈为建议项，可在评审后替换。

## 0.2 相对 V3.0 的保留/简化/延后/不做表

| V3.0 项目 | 处理建议 | 说明 |
|---|---|---|
| 官方页面采集、定时抓取 | 保留并优先实现 | 直接对应原始需求主线 |

| 队列、并发控制、退避、熔断（简化） | 保留简化版 | 自动错峰的必要机制 |

## 0.3 设计原则精简版

1. **数据边界清晰：** 只分析本工具自身发出的请求与官方公开的服务状态信息。不得宣称可以观察或推断供应商的全局用户流量、内部队列或真实剩余配额。
2. **安全规则优先：** 任何预测、评分或调度决策都不得覆盖安全策略、命令白名单与预算硬上限。
3. **默认最小权限：** 任务与 Agent 仅获得完成任务所需的最小权限。
4. **失败时安全降级：** 指标缺失、状态不确定或数据质量不足时采用保守策略，不得默认判定为低压力或放宽限制。
5. **有限重试：** 每次重试都有明确原因、次数上限、时间上限与成本上限；不确定是否已产生外部副作用时不得直接重试。
6. **可解释、可追踪：** 每次调度决策、策略变更与夜间开发执行均可审计、可追踪。
7. **分阶段交付：** MVP 不以历史预测、复杂多 Agent 协作或自动合并代码为前置条件。
8. **供应商行为以适配器为准：** 不假设所有 API 都具有相同错误码、重试语义、Token 统计字段、价格或状态接口。
9. **不承诺端到端「恰好一次」：** 对外部 API、Git 等系统，以幂等、去重、状态核查与 `UNKNOWN` 状态降低重复副作用风险；无法由对端配合时不宣称实现 exactly-once。

## 0.4 术语

- **Provider：** 模型/API 服务提供商，例如 DeepSeek。
- **Provider Adapter：** 对某个服务商 API 行为进行封装的适配层。
- **Task：** 用户提交的逻辑任务。
- **Attempt：** 对某个任务的一次执行尝试。
- **UNKNOWN：** 系统无法可靠确认上一次执行是否完成或是否产生外部副作用的状态。
- **错峰调度：** 根据官方计价时段规则与自身观测反馈，调整非紧急任务执行时机与并发。
- **高峰/空闲计价时段：** 官方价格页定义的分时计价时段，作为可配置的初始规则，不是全局实时负载曲线。
- **预算硬上限：** 未经授权不得突破的成本限制。
- **安全失败（fail closed）：** 关键安全控制不可用时拒绝或暂停高风险操作，而不是放行。

# 1. 数据边界与关键前提

## 1.1 可获取的官方公开信息

DeepSeek 官方通过公开渠道提供以下信息，可用于本工具：

- **官方计价时段：** 当前官方价格页列出的高峰/空闲计价时段（工作日北京时间 09:00–12:00、14:00–18:00 为高峰，其余为空闲；空闲价格较低）。**应注意**：这是「计价时段」定义，可作为可配置的初始调度规则，但不等同于全体用户实时访问量曲线。应以官方页面为准并定期复核。
- **服务状态页：** 展示服务是否正常并提供历史服务事件，用于识别服务异常时段。这不等于全局请求量监控。
- **API 过载与限流反馈：** 429 表示请求速率限制、503 表示服务过载，作为本工具自身请求的反馈信号。据此判断何时减少并发或延迟非紧急任务。
- **自身 API 用量：** 响应提供的 Token 用量，用于建立自身调用历史、成本统计与任务效果记录。

## 1.2 不可监控 / 不可声称的数据

- 官方未公开全局请求量、用户访问峰值、内部排队长度或真实剩余配额。不得通过爬虫或推断声称可观察这些数据。
- 若爬虫抓不到官方信息，不得伪造或推断，应记录为采集失败。
- 官方计价时段 ≠ 全体用户实时访问曲线。不得把「空闲计价时段」解读为「该时段一定不会限流」。
- 不得承诺「某时段一定不会限流」或「某时段一定可用稳定配额」。

## 1.3 两类数据必须分开处理

本工具只处理两类数据，且必须分开统计，不得混淆：

- **(a) 官方公开信息采集：** 官方计价时段、价格、服务状态页快照，来自官方渠道。
- **(b) 自身调用数据统计：** 本工具自身发出的请求记录、延迟、429/503、Token 与成本，来自自身调用历史。

不得把 (b) 自身观测误认为 DeepSeek 全体用户的访问规律。官方信息和自身观测分别记录数据来源，避免混为一类数据。

# 2. 功能需求 F1–F8

各功能均标注所属实施阶段（★阶段1 监控 / ★阶段2 错峰 / ★阶段3 夜间开发 / ★阶段4 优化）。

## F1 官方信息采集与时段规则（★阶段1）

- 定时抓取官方价格页与服务状态页，保存快照与抓取时间。
- 从官方资料解析高峰/空闲计价时段与价格，生成可配置的初始调度规则 `window_rules`。
- 官方时段规则必须标注数据来源与采集时间；以官方页面为准并定期复核。
- 服务状态页用于识别服务异常时段；429/503 语义作为自身请求反馈。
- 若抓取失败或内容无法解析，记录为失败，不得伪造默认值并当作权威数据。

## F2 自身 API 调用记录与统计（★阶段1）

- 所有模型请求经过统一 API Client，业务模块不得各自直接调用供应商 SDK。
- 记录请求开始/结束时间、状态码、延迟、模型、输入/输出 Token（若服务商提供）、重试次数与估算成本。
- 统计 429 比率、5xx（含 503）比率、超时率、成功率与延迟分位数；样本量不足时不输出误导性稳定分位数。
- 所有聚合指标包含时间窗口、样本数与数据质量状态；指标缺失不能默认视为零压力。
- 时间戳统一存储为 UTC，展示时按本地时区换算；对请求日志定义去重键避免重复统计。

## F3 时段规律分析（工作日/夜间/周末/节假日）（★阶段1）

- 生成按 工作日工作时间 / 夜间 / 周末 / 节假日 分组的自身调用统计，作为错峰调度依据。
- 每天的数据总量不足时，标记为 `INSUFFICIENT_SAMPLE`，不输出高置信度结论。
- 节假日由可配置的节假日日历标记；节假日与周末处于非工作日窗口。
- 数据质量不足时采用保守策略，不得默认判定为低压力。

## F4 错峰调度（★阶段2）

- 依据官方时段规则与本工具观测到的 429、503、延迟等反馈，调度非紧急任务。
- 高峰时段：降低非紧急任务优先级、减少并发、延迟启动非紧急任务。
- 保护重要任务：紧急/重要任务在高峰仍可执行，但受预算与硬性规则约束。
- 调度决策优先级（从高到低）：安全与授权限制 > 预算硬上限 > 实时服务健康与熔断状态 > 自身资源容量 > 任务优先级与截止时间 > 官方时段规则与自身观测 > 历史预测与软性评分（阶段4）。
- 每次决策记录原因代码、使用的规则版本、关键输入摘要与数据质量。

## F5 限流退避与暂停（简化熔断）（★阶段2）

- 对 429 优先遵守官方 `Retry-After`；若不存在，使用有限指数退避与随机抖动。
- 重试次数、总重试时间与总成本均设置上限；明显不可重试的 4xx（如参数错误、权限错误）不自动重试。
- 对认证错误优先停止并告警，不得反复尝试同一失效密钥。
- 简化熔断状态：`CLOSED`（正常）、`OPEN`（暂停非紧急任务）、`HALF_OPEN`（有限探测后恢复）。熔断打开/半开/关闭均产生事件与审计记录。
- 出现连续 429 或持续 5xx/过载时，暂停低优先级任务并进入退避，保护重要任务。
- 取消请求后若上游无法取消，记录可能仍在执行或计费的风险。

## F6 任务管理与失败恢复（简化）（★阶段2，状态机见第 3 节）

- 每个任务拥有唯一 `task_id` 与幂等机制；同一幂等键在有效期内重复提交不得创建重复任务。
- 单机/小团队场景不需要分布式租约与发件箱；使用 SQLite 事务或等效原子机制保护状态转换。
- 队列消息允许至少一次投递，消费者必须幂等；重复投递不重复创建或重复执行。
- 状态不确定时不得盲目重试；进入 `UNKNOWN` 并提供人工处理入口。
- 任务支持最大执行时长、最大 Attempt 数与最大累计成本上限。
- 支持人工取消、暂停与恢复；任务取消记录取消时间与可能的残余外部执行。

## F7 夜间/非工作日自动开发（★阶段3）

- 在允许的夜间 / 非工作日窗口内，自动启动已授权的开发程序，使用可用 API 容量执行开发任务。
- 每个夜间开发任务显式声明允许使用的工具、目录与命令白名单：
  - 读取指定仓库中的授权文件；
  - 在隔离工作目录内编辑文件；
  - 执行白名单开发命令（如测试、格式化、静态分析）；
  - 生成分支或补丁草案。
- 默认禁止：
  - 任意 shell 命令或不受控特权命令；
  - 访问宿主机敏感路径；
  - 修改权限、安全策略或预算硬上限；
  - 将代码、日志、Prompt 或密钥发送到未批准外部地址；
  - 直接合并主分支、发布生产版本或执行破坏性数据库操作。
- 夜间开发结果仅生成分支/补丁草案供人工检查；禁止自动合并与自动部署。
- 仓库代码、README、Issue、日志与模型输出均视为不可信输入；不可信内容不得覆盖策略、授权或白名单。工具参数需经过结构校验、路径规范化和权限检查。
- 对产出补丁执行 Secret Scan 与适用的静态分析；检测到密钥泄露或疑似外传时停止任务、隔离工作区并告警。

## F8 反馈与优化（★阶段4）

- 记录实际调用效果（成功/失败/429/503）、任务进度与成本，作为反馈数据。
- 有足够自身历史数据后，增加趋势分析与高峰预测，并逐步改进调度规则。
- 预测必须先通过离线回测与影子模式评估，未通过评估的预测不得控制真实调度。
- 预测不能覆盖安全规则、实时熔断与预算硬上限。

# 3. 任务状态机（精简状态集与转换语义）

精简状态集（V3.0 的 `CLAIMED`、`WAITING_EXTERNAL_RESULT`、`REVIEW_REQUIRED` 折叠或并入对应状态）：

```text
PENDING -> QUEUED -> RUNNING -> SUCCEEDED
                    |    |-> RETRY_WAIT -> QUEUED
                    |    |-> FAILED
                    |    |-> CANCELLED
                    |    |-> PAUSED -> QUEUED
                    |    |-> EXPIRED
                    |    |-> UNKNOWN（人工处理后回 QUEUED / FAILED / SUCCEEDED）
```

状态语义：

- `PENDING`：任务已创建，尚未进入可执行队列。
- `QUEUED`：满足基本条件，等待调度（含错峰判断）。
- `RUNNING`：执行已开始。
- `RETRY_WAIT`：符合有限重试条件，等待退避时间结束。
- `PAUSED`：被策略或人工暂停（含高峰降载暂停非紧急任务）。
- `SUCCEEDED`：任务完成且结果已持久化并保存以供检查。
- `FAILED`：已确认失败且不再自动重试。
- `CANCELLED`：任务被取消；外部副作用是否已发生需单独记录。
- `EXPIRED`：任务超过有效期或截止时间。
- `UNKNOWN`：无法确认执行结果或外部副作用状态，必须先查询、对账或人工处理。

一致性要求：

- 每个任务拥有 `task_id`；每次执行拥有 `execution_id`；每次尝试拥有 `attempt_id` 与 `attempt_no`。
- 状态转换必须由数据库事务或等效原子机制保护；记录 `created_at`、`started_at`、`finished_at`、`deadline_at`。
- 执行进程崩溃或重启后，先核查上次执行记录与外部副作用状态，不得盲目重试。
- 已创建 PR、已发送消息等外部副作用必须查询目标系统或用对端幂等机制；无法确认时进入 `UNKNOWN`。

# 4. 安全要求

安全边界不能只由配置项声明，必须通过实际隔离机制与负向测试验证。以下为单用户/小团队场景的安全要求，不可省略（因为夜间开发会执行代码）。

## 4.1 夜间自动开发执行边界（沙箱）

- 执行以非 root 身份运行；禁止 privileged 容器与 Docker Socket 挂载。
- 禁止挂载宿主机根目录、生产配置目录、SSH 私钥目录和其他用户 Home 目录。
- 每个任务使用独立、权限受限的工作目录；使用本地受限容器或受限沙箱。
- 限制 CPU、内存、磁盘、进程数、文件描述符与执行时长。
- 默认关闭出站网络；确有依赖下载需求时使用受控代理与域名/目的地白名单。
- 阻止访问云平台元数据服务、宿主机管理端口与内网敏感服务。
- 不向 Agent 继承宿主机完整环境变量。
- 任务结束后销毁执行环境；缓存隔离并定期清理。
- Git Hook 默认禁用；依赖版本锁定并对新增依赖执行审核与扫描。
- 应使用命令白名单而非仅黑名单；高价值安全测试可通过负向测试验证（见第 9 节）。

## 4.2 密钥与凭据

- Provider API Key 仅存于环境变量或本地受控配置文件，不进入代码、日志或 Prompt。
- 凭据按用途隔离，支持轮换与吊销；不通过命令行参数、错误堆栈、任务报告传递密钥。
- Worker/Agent 默认不得直接读取长期 Provider Key；模型调用经统一入口完成。
- 记录凭据访问的主体、时间、用途与结果，但绝不记录明文。
- 怀疑密钥泄露时支持立即吊销、轮换并暂停关联任务。
- 提供 `.env.example`，只包含变量名称与非敏感示例值，不包含真实密钥。

## 4.3 日志与数据脱敏

- 默认不保存完整 Prompt 与完整模型响应；确需保存时显式启用、说明目的并配置保留期限。
- 日志中禁止记录密钥、Authorization Header、Cookie 与未经脱敏的敏感请求体。
- 对用户输入、模型输出与异常内容执行敏感信息检测。
- 指标标签不得使用高基数或敏感内容（如完整 Prompt、用户邮箱、原始 URL 参数）。
- 原始错误只能存放于受控日志系统并执行脱敏；业务数据库优先保存 `error_code`、`error_category`、`safe_error_message` 与受控的 `raw_error_reference`。

## 4.4 人工控制点

- 生产代码合并、生产部署、权限扩大、预算上调和安全策略变更默认需人工审批。
- 夜间开发结果（分支/补丁草案）必须经人工检查后才可继续；禁止自动合并、自动部署。
- 单用户场景使用本机令牌或本地身份鉴权，不做多租户与复杂 RBAC。
- `UNKNOWN` 状态任务提供人工处理入口；关键安全控制失效时暂停高风险操作而非默认放行（安全失败）。

# 5. 系统架构与模块（单机/小团队简化）

## 5.1 简化架构图

```text
用户（CLI / 简单配置界面 / 本地令牌鉴权）
                 |
                 v
        统一 API Client (Provider Adapter)
                 |
        +--------+----------+
        |                   |
        v                   v
   调度器 (Scheduler)     采集器 (官方信息 + 自身请求记录)
        |                   |
        v                   v
    任务队列(持久化)      统计与时段规律分析
        |                   |
        v                   v
   执行器(夜间开发)  <--  沙箱 / 本地受限容器
        |
        v
   Git 分支 / 补丁草案（保存供人工检查）
        |
        +--> 模型 Provider (DeepSeek)

公共基础设施：SQLite（任务/统计/成本事实来源）+ 结构化日志（可选 Prometheus）
```

## 5.2 模块职责（精简）

1. **统一 API Client / Provider Adapter：** 统一请求、超时、有限重试、流式/非流式、Token 用量解析与成本估算；封装供应商特有错误分类、`Retry-After`、Usage 与模型能力。
2. **采集器：** 定时抓取官方计价时段、价格与服务状态页，并记录自身请求状态、延迟、429/503、Token 与成本。
3. **调度器：** 综合硬性保护规则、服务健康、预算、官方时段规则、自身观测、任务优先级与截止时间做调度。
4. **任务队列与状态机：** 维护持久化任务表、状态转换、幂等键、有限重试与恢复。
5. **统计与时段规律分析：** 生成工作日/夜间/周末/节假日分组统计与数据质量标记。
6. **执行器（夜间开发）：** 在授权窗口内执行已授权开发任务，应用命令白名单、目录限制、运行时长与成本限制。
7. **沙箱管理：** 创建并销毁受限执行环境，限制网络、文件、资源与系统调用。
8. **配置管理：** 管理时段规则、节假日日历、价格表、任务白名单与成本上限，版本化并支持回滚。

## 5.3 建议技术栈（可替换，不作为硬性需求）

- 后端：Python 3.11+（可选 FastAPI 或简单 CLI）。
- 数据库：SQLite 起步，可迁移 PostgreSQL。
- 调度：内置调度器或系统 cron。
- 日志：结构化日志；可选 Prometheus/Grafana。
- 沙箱：受限容器或受限本地环境（非 root、禁 privileged、禁 Docker Socket、限资源）。
- 部署：单机本地方案即可；生产变更仍需人工审批。
- 不得虚构 QPS 数值或性能承诺；目标吞吐在需求确认前不虚构固定容量。

# 6. 数据模型（精简表）

建议至少包含以下表（字段繁简自定；统一使用幂等去重键）：

- `tasks`：逻辑任务与当前状态（`task_id`、幂等键、任务类型、优先级、`status`、`attempt_no`、`created_at`、`started_at`、`finished_at`、`deadline_at`、`estimated_cost`、`actual_cost`、`error_code`、`safe_error_message`）。
- `task_runs` / `task_attempts`：单次执行与尝试记录（`execution_id`、`attempt_id`、开始/结束时间、错误分类、重试原因、是否可能计费）。
- `api_request_logs`：请求元数据与成本估算（时间、状态码、延迟、模型、输入/输出 Token、重试次数、估算成本、去重键）。
- `official_snapshots`：官方信息采集快照（类型：计价时段/价格/服务状态、抓取时间、原始内容引用、解析结果、数据来源）。
- `schedule_decisions`：调度决策记录（决策结果、`reason_codes`、关键输入摘要、样本数、数据质量、规则版本、是否人工覆盖）。
- `cost_records`：成本记录（关联 Provider、模型、计价版本、Token、请求/Attempt ID、估算依据与状态 `estimated`/`actual`/`unknown`）。
- `window_rules`：官方时段规则（高峰/空闲定义、节假日标记、版本、生效时间、来源与采集时间）。

不引入分布式租约、发件箱或灾备相关表；单机场景以 SQLite 事务保证状态一致性。每笔调度决策与成本记录不得保存完整密钥、完整 Prompt 或不必要的个人信息。

# 7. 配置管理（简化）

所有影响行为的配置版本化，包括：

- 时段规则（官方高峰/空闲计价时段）。
- 节假日日历。
- 价格表与计价版本。
- 任务白名单、目录白名单、命令白名单与沙箱策略。
- 并发上限、429 退避与简化熔断阈值。
- 预算阈值（软告警与硬上限）。
- 数据保留与日志脱敏规则。

每个配置版本包含：`config_id`、`version`、`created_at`、`effective_at`、`change_reason`、`previous_version`、`rollback_supported`。

配置变更流程（简化）：提交变更 → 显示差异与影响范围 → 静态校验 → 需要时人工审批 → 分阶段生效 → 观察指标 → 异常回滚到已知安全版本 → 记录审计事件。禁止 Agent 自行修改安全策略、预算硬上限或自身权限。

# 8. 实施路线（四阶段 + 退出条件）

## 阶段 1：监控

交付物：
- 官方计价时段、价格与服务状态页采集器。
- 统一 API Client，记录自身请求、延迟、429/503、Token 与估算成本。
- 工作日 / 夜间 / 周末 / 节假日统计与数据质量标记。

退出条件：官方信息与自身调用数据分开记录并均可追踪；两类数据来源清晰不混淆；统计包含数据质量标记。

## 阶段 2：错峰

交付物：
- 任务状态机、幂等创建、有限重试与恢复（含 `UNKNOWN` 处理）。
- 基于官方时段规则与 429/503/延迟反馈的错峰调度。
- 简化限流、退避、暂停/冷却（简化熔断）与预算硬上限。

退出条件：高峰时段非紧急任务被降载/延迟而重要任务受保护；429/503 触发退避与有限重试；状态不确定时不会盲目重试；预算硬上限不会被并发竞争突破；决策可解释并可定位到规则版本。

## 阶段 3：夜间开发

交付物：
- 授权窗口内自动启动已授权开发任务的执行器。
- 沙箱、命令白名单、目录限制、运行时长与成本限制。
- 开发结果仅生成分支/补丁草案，保存供人工检查。

退出条件：沙箱负向测试与密钥泄露测试通过；夜间开发产出可验证结果；禁止自动合并与自动部署已落实。

## 阶段 4：优化

交付物：
- 基于足够自身历史数据的趋势分析与高峰预测。
- 影子模式评估与调度策略自动调整。

退出条件：预测在明确数据集上优于或合理匹配简单基线；未通过评估的预测不控制真实调度；预测不覆盖安全规则、实时熔断与预算硬上限。

# 9. 测试与验收（精简）

- **采集正确性：** 官方时段解析正确、来源与时间记录完整；抓取失败时记录失败而不伪造；不能把自身观测与官方信息混淆。
- **错峰行为：** 高峰时段非紧急任务被降载/延迟、重要任务受保护；决策可解释并定位到规则版本。
- **429/503 处理：** `Retry-After` 尊重；有限指数退避；简化熔断打开/半开/恢复；不可重试 4xx 不进入无限重试。
- **有限重试：** 每个重试有可追踪原因与成本记录；次数、时间、成本上限生效。
- **任务恢复：** 同一幂等键重复提交不创建重复任务；重复投递不重复执行；状态不确定进入 `UNKNOWN` 且不盲目重试；系统重启后能区分可安全恢复任务与需人工确认任务。
- **沙箱负向测试：** 尝试读取密钥/宿主敏感文件/Docker Socket/未批准网络均被阻止而非仅靠 Prompt 拒绝；资源超限可终止并清理；Secret Scan 检测密钥后停止并告警。
- **成本上限：** 软告警生效；预算硬上限不会被系统自动突破。
- **可运营性：** 数据库备份可恢复；日志写入失败不无限阻塞主流程；配置变更可审计并可回滚。

# 11. 已知限制与待确认项（精简）

- 目标用户为单人或小团队；并发量与吞吐目标待确认，不虚构固定 QPS。
- 官方并未公开全局请求量/用户峰值/内部排队信息；因此本工具只监控自身观测与官方公开信息。
- 官方计价时段为可配置初始规则，不等于全局实时访问曲线；需定期对照官方页面复核。
- 沙箱采用受限容器或受限本地环境，具体隔离强度与网络白名单范围待确认。
- 首期以 DeepSeek 为主；是否支持多 Provider 延后决定。
- 生产部署、代码合并、数据库变更的审批责任人为本机使用者；保留人工审批即可。
- 合规要求（数据跨境、代码保密、供应商数据处理条款）需根据实际使用场景单独评估，不能仅凭本文视为已合规。
- 以上未确认项应在配置中显式标记为待定并采用安全默认值，不得由开发 Agent 自行作扩大权限或成本的决定。

# 12. 最终硬性规则（精简）

以下规则不可被普通任务配置、历史预测或调度决策覆盖：

1. 所有模型请求必须经过统一 API Client。
2. 所有任务必须有唯一 ID、幂等机制与可追踪的执行记录。
3. 状态不确定时不得无条件重试，进入 `UNKNOWN` 并人工处理。
4. 所有重试必须受次数、时间与成本限制。
5. 沙箱与命令白名单不得被绕过；Agent 不得访问 Docker Socket、宿主机敏感目录或云平台元数据。
6. 密钥不得进入代码、日志或 Prompt；敏感数据不得进入普通日志、指标标签与告警载荷。
7. Agent 只能访问任务明确授权的仓库、分支、目录、命令与工具；不可信内容不得扩大权限或绕过审批。
8. 生产代码合并与生产部署默认需人工审批；夜间开发仅生成分支/补丁草案，禁止自动合并与自动部署。
9. 预算硬上限不得被自动突破。
10. 官方公开信息与自身观测不得混淆，不得声称可观察或推断供应商全局监控、内部队列或真实剩余配额。
11. 任何「自动化成功」都必须有可验证的执行结果，不能只依赖 Agent 自述。
12. 所有配置变更必须版本化并支持回滚；关键安全控制失效时暂停高风险操作而非默认放行。

# 13. 结论

NexusAI Lite 的合理演进路径为：

```text
采集官方信息与自身记录（监控）
    -> 基于官方时段与自身反馈的错峰调度
    -> 授权窗口内的夜间自动开发（沙箱 + 人工检查）
    -> 积累历史数据后的趋势分析与规则优化
```

首期交付的成功标准不是「系统看起来足够智能」，而是能够回答并验证以下问题：

- 每个请求发生了什么，官方信息与自身观测是否分开记录？
- 为什么调度器允许、延迟或暂停一个任务？
- 发生超时后，系统是否知道请求可能已经执行？
- 预算是否能在并发情况下被可靠保护？
- Worker 重启后任务能否安全恢复、不确定结果是否进入 `UNKNOWN`？
- 夜间开发是否被沙箱、白名单与人工检查所约束，而非仅靠 Prompt？
- 高峰是否降载了非紧急任务、保护了重要任务？

只有先建立监控、错峰、夜间开发与反馈的闭环，再引入预测与自动优化，本工具才具可维护、可审计并逐步进入生产使用的基础。
