# NexusAI 开发任务清单（Development Task List）

> 来源文档 reference.md（V3.0）｜生成日期 2026-10-12｜状态：待评审

---

## 一、文档信息与使用说明

本清单由 reference.md（PRD + Technical Design V3.0，共 16 章）派生而成，是 NexusAI（智枢 AI 调度平台）的开发、测试与验收基线。开发团队或 AI 开发 Agent 可自上而下逐条执行。

**使用方式：**

- 每个任务为复选框项 `- [ ]`。完成并验证验收标准后，将 `[ ]` 标记为 `[x]`。
- 任务具有唯一 ID（如 `P1-03`）。当任务 A 依赖任务 B 时，通过 `前置依赖 = B 的 ID` 引用，保持 ID 稳定不变。
- 优先级：P0 = 必须最先完成的安全/设计基线；P1 = 核心 MVP 主线；P2 = 主线功能的强化；P3 = 分析预测；P4 = Agent；P5 = 多 Provider 与策略优化；X = 横向（测试、交付物、非功能、数据、配置）。
- 复杂度：S（小）/ M（中）/ L（大），用于排序与排期参考，不含人天估算。
- 每个阶段首部列出该阶段在 §11 中的退出条件，任务完成后据此判定阶段是否通关。
- `来源` 列标注对应 reference.md 章节，便于回溯原文。

**重要约定：**

- §14 中的待确认决策属于**人工业务决策**，不是开发 Agent 可自行拍板的项。清单中将这些项列为「阻塞项」表格，并建议安全默认值。开发 Agent 不得在未获授权时自行扩大权限、成本或安全边界。
- 安全、权限、预算硬上限、生产变更等关键项默认需要人工审批，遵守 §15 硬性规则。
- 技术栈（§3.3）仅作建议，不得被当作硬性需求。
