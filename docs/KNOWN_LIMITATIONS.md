# NexusAI Lite 已知限制、阻塞项与路线图

> 本文档诚实列出本版本的已知限制、待确认项（来自 [`reference.md`](reference.md) §11 与任务清单「阻塞项」）与延后路线图。待确认决策属**人工业务决策**，开发/Agent 不得自行拍板扩大权限或成本；未确认前采用安全默认值并标记待定。

## 已知限制（当前实现边界）

- **目标用户**：单人或小团队。并发量与吞吐目标未定，**不虚构固定 QPS 容量**。
- **数据边界**：只监控官方公开信息（`official_snapshots` / `window_rules`）与本工具自身调用（`api_request_logs` / `cost_records`）；**不声称**可观察或推断供应商全局流量、内部队列或真实剩余配额。官方计价时段只是可配置的初始调度规则，**不等于全局实时负载曲线**，需定期对照官方页面复核。
- **沙箱形态**：当前为**受限本地同用户子进程沙箱**（`sandbox.py`），**不是容器、不是 OS 隔离边界**。`ContainerSandbox` 是未实现的接缝（调用即抛 `NotImplementedError`）。被授权解释器可读取当前用户可读的任何宿主文件，沙箱不阻止此同权限读取；运行不可信任意代码须用真正的容器/microVM 后端（见 `SECURITY.md`）。
- **网络隔离是尽力而为**：依赖 `unshare -n` 真实可用性；多数非特权环境不可用，此时 `network_isolated=False`，被沙箱执行的命令仍可访问网络（详见 `SECURITY.md`）。不得依赖其作为唯一防线。
- **夜间开发无 `nightdev` 配置节**：`nightdev.py` 的窗口/假日/规格由调用方以参数注入，尚未做成版本化配置节（与 X-04 配置扩展衔接）。
- **配置生效事件**：`activate_config` / `rollback_config` 均在生效时发布 `PolicyChanged`（`ConfigActivated` / `ConfigRolledBack` 分别承载激活/回滚动作）。
- **无 CLI 调度器 / 内置定时器**：没有 `schedule` 之类的子命令；采集与夜间规划、以及维护（`maintain`）需系统 cron / 用户级 timer 调用。
- **CLI 覆盖部分功能**：任务状态机（`tasks.py`）、调度器（`scheduler.py`）、预算（`budget.py`）、熔断（`circuit_breaker.py`）、告警（`alerts.py`）、影子（`shadow.py`）、预测（`forecast.py`）、执行器（`executor.py`）目前是模块级能力，未全部封装为 CLI 子命令，主要供程序化调用与测试。

## 阻塞项 / 待确认决策（§11，安全默认值）

| 决策项 | 影响 | 当前安全默认值 |
|---|---|---|
| 并发量与吞吐目标 | 容量规划 | 单机起步，不虚构 QPS |
| 官方计价时段复核周期 | 调度规则准确性 | 以官方价格页为准并定期复核；标记来源与采集时间 |
| 沙箱容器/本地、网络范围 | 隔离强度 | 非 root、禁 privileged、禁 Docker Socket、限制资源；网络隔离尽力而为 |
| 夜间开发允许的仓库/目录范围 | 命令/目录白名单 | MVP 仅生成补丁草案供人工检查；路径最小化 |
| 预算币种、价格来源、硬上限数值 | 预算 | 硬上限不被自动突破；价格表 `pricing.table` 为空（`pricing_version="unverified-seed"`），成本未知 |
| 生产合并/部署/DB 变更审批人 | 人工控制点 | 全由使用方本人审批；禁止自动合并/部署 |
| 数据保留期限与脱敏程度 | 日志/合规 | 默认不存完整 Prompt/响应；`log_retention_days=90`；敏感数据不进日志/指标/告警 |
| 多 Provider / 多租户 | 范围边界 | 首期仅 DeepSeek；二者延后 |

## 路线图（延后 / 不做）

延后自 [`reference.md`](reference.md) §0.2：

- **多 Provider 统一网关**：当前仅 DeepSeek；`ProviderAdapter` 契约已就绪（`PROVIDER_ADAPTER.md`），可扩展。
- **多租户、复杂 RBAC、审批中心、双人复核**：不纳入 MVP；保留「生产变更需人工审批」。
- **复杂机器学习 / 多 Agent 协作**：延后。
- **企业级账单对账、灾备集群**：暂不纳入 MVP。
- **自动合并、生产部署**：默认不做（风险高，非原始需求）。
- **阶段 4 的预测自动控制真实调度**：预测与影子模式是只读/advisory-only，未通过离线回测与影子观察、人工审核前，不控制真实调度（`forecast.py` / `shadow.py` 只读写保护性表，不碰 `tasks` / `schedule_decisions` 的实测决策）。

## 阶段状态

- **阶段 1 监控（S1）**：官方采集、统一 API Client、请求统计、时段分析、配置最小实现 —— 已实现。
- **阶段 2 错峰（S2）**：任务状态机、有限重试、429/503 退避、简化熔断、错峰调度器、预算硬上限、基础告警 —— 已实现。
- **阶段 3 夜间开发（S3）**：授权窗口规划、执行器守卫管线、本地沙箱、命令/目录白名单、Secret Scan、补丁草案输出 —— 已实现；容器后端未实现。
- **阶段 4 优化（S4）**：预测与影子模式 —— 已实现为只读/advisory-only。

> 上述实现状态以当前代码为准；合入验收与 §12 十二条硬性规则核对见 `development-task-list.md`（X-01/X-02/X-03）。
